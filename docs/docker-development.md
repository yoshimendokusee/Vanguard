# Docker development verification — 2026-10-09

Root `docker compose up -d --build` previously built the existing hub and a Vite
**vanilla** frontend, and started local Ollama. No React conversion, native app,
backend service split, database migration or API wire change was introduced.
Routine edits in `hub/public` need no rebuild/restart. Git commits/pulls share code;
each teammate's localhost is an independent environment.

## Current default Docker startup — 2026-10-10

The root Compose file now includes only `hub/docker-compose.yml`. It builds the
latest dashboard assets into the production image and serves the app and its API
from Express at **localhost:3000**. Port 3000 is the only published host port;
Ollama remains on the internal network. Web source edits take effect after an image
rebuild and container recreation; no host Vite process is used by default.

Before switching from an older stack, stop both Compose project names so the old
frontend and hub mappings release their ports. These commands preserve `hub/data`
and named model volumes:

```sh
docker compose down --remove-orphans
docker compose -f hub/docker-compose.yml down --remove-orphans
docker compose up -d --build --force-recreate --remove-orphans
```

The optional Vite frontend Compose file is not part of root startup. CI still tests
Vite HMR in a separate disposable container; that does not publish another app port
for normal use. Docker Compose must be available to stop old containers and start
the new stack.

The remaining verification below records the previous Vite development setup as
historical evidence; it does not describe the current root Compose services.

| Service | Development | Storage/dependencies |
| --- | --- | --- |
| frontend | host localhost:3301 → Vite 0.0.0.0:3301; HTTP and HMR WebSocket share the port | read-only source/config binds; locked dependencies baked into development image |
| hub | host localhost:3000 → Express:3000; Vite proxies `/api` to `http://hub:3000` including SSE | original `hub/data:/data`, SQLite `/data/vanguard.db`; migrations/business logic unchanged |
| ollama | internal inference network:11434, no host port | original pinned image/GGUF and named model cache; no internet route |

The historical `compose.yaml` merged `hub/docker-compose.yml` with
`hub/compose.dev.yaml` through Compose include (2.20.3+). The legacy `hub/` entry point remains production: Express
serves the optimized `dist` generated by Vite. Source assets remain the native
fallback when no build exists. The multi-stage production image omits Vite and
compiler tools. Both entry points share the same existing data path: run one at a time.
Host API binding now defaults to localhost even without `.env`; opt into an
isolated LAN address for synthetic physical-device demos. Native clients continue
using `http://<computer-lan-ip>:3000`, never their own localhost.

Vite uses a strict port, Docker DNS API proxy and client WebSocket port 3301.
CSS updates preserve browser state; vanilla JavaScript/HTML automatically reload.
URL/localStorage state survives reload; unsaved forms may not. Polling defaults to
250 ms for Docker Desktop bind mounts; disable with `VITE_USE_POLLING=false` where
native Linux/WSL filesystem events work. Host dependencies cannot hide container
libraries because only frontend source/config are mounted. Backend/dependency
changes require rebuilding; frontend source changes do not.

## Boundaries and remaining verification

- Windows, native Linux/WSL and x86 Docker builds have not been physically checked
  here. Polling is configured for Docker Desktop; hosted Ubuntu CI remains a
  separate result.
- Native watch/iPhone hardware and Flutter/Swift checks were not rerun: no native
  code, API payload, migration or model was changed. LAN configuration compatibility
  does not prove physical-device delivery/background behavior.
- Git LFS model weights must exist in the checkout for the existing Qwen service.
  A pointer-only clone cannot supply offline inference. Docker pulls missing pinned
  images on first setup; it does not download model weights at runtime. Git/Git LFS
  are source-checkout tooling; Node/npm/Vite/backend dependencies are entirely Docker
  managed. Report capture/dashboard remain independent of AI availability.
- Existing HTTP and SQLite are unauthenticated/unencrypted. Defaults restrict host
  access; use only synthetic data and isolated LANs. This is not production security
  or approval for real patient data.

Changes cover Compose, Dockerfile/ignore rules, the locked Vite development
dependency/config/scripts, frontend CSS/JS extraction, Express asset selection,
contract tests, HMR self-check, CI/repository validation, environment examples,
README, architecture/API documentation and this report. SQLite schemas, native
clients, triage logic and ACK semantics were left in place.
